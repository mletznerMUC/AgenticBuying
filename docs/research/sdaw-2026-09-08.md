# SDAW against the agentic protocols — 8 September 2026

- **Run date:** 2026-09-08
- **Scope:** New topic note, first pass. Builds the evidence base for `sdaw.html`,
  a market deep dive nested under the OOH channel page: what SDAW
  (Standardisierter Datensatz zur Außenwerbung) can and cannot express in AAMP
  and AdCP, field by field, and which upstream items decide whether German
  classic poster inventory becomes agentically bookable.
- **Related pages:** `sdaw.html` (target), `ooh.html` (parent), `adcp.html`,
  `aamp.html`, `comparison.html`.
- **Provenance — read this first.** Unlike every other note in this directory,
  this one did not originate in a research run. Its substance is a desk-research
  gap analysis contributed to the project on 2026-09-08, prepared against public
  artifacts only. This note records what that analysis claims, which parts were
  independently re-checked here, and which were not. The site page derived from
  it badges accordingly.

## Summary

The organizing finding is that the gap runs in **both directions**, so the
exercise is a two-way mapping rather than a migration. SDAW has no transport, no
authentication, no digital-playout concept and no impression currency — the
things an agentic protocol assumes. AAMP and AdCP have no bookable panel object,
no geo-coordinates on inventory, no illumination or physical dimensions and no
posting-cycle calendar — the things SDAW is made of. Neither standard is a
superset of the other.

Two secondary findings follow. First, AdCP is materially further along on the
medium than AAMP: DOOH is modelled in its released schemas, and static
out-of-home exists as an experimental surface in the 3.2 pre-release line plus a
design draft in the repository, while AAMP's out-of-home presence is an
enumeration value, an inert metadata reference and a stated intention. Second,
the nearest real IAB out-of-home data model is not AAMP but **OpenDirect 2.1**,
whose vocabulary AAMP inherits without binding out-of-home semantics to it, and
which AdCP's static-OOH draft explicitly borrows from while rejecting its
transport.

The evidence is asymmetric in a way that matters: the protocol side rests on open
repositories that anyone can re-read, and the SDAW side rests on a reconstruction
from a 2011–2013 open-source toolchain, because the specification is a
members-only association document.

### 2. SDAW as a format — reconstruction, not specification

| Claim | Status | Source | Date verified |
|---|---|---|---|
| Version 004 is the version the public toolchain implements, with files dated 2011; roughly 220 of at least 495 bytes of the `STA` master-data record are undisclosed, including one 140-byte block, and about 24 of the roughly 30 file types are not publicly documented | reported | [sdxist](https://github.com/mckoch/sdxist) record layouts; [open-sdaw](https://github.com/mckoch/open-sdaw); via the contributed analysis | 2026-09-08 |
| The record is fixed 1-based character positions, space-padded, with no escaping and no stated character set; a single wrong byte shifts every following field | reported | [sdxist](https://github.com/mckoch/sdxist); via the contributed analysis | 2026-09-08 |
| Site identity is scoped to the lessee — a three-character prefix plus a site number — so no market-wide panel identity exists; panel numbers at a site are capped at 99 | reported | [sdxist](https://github.com/mckoch/sdxist); via the contributed analysis | 2026-09-08 |
| Time is an index rather than a date: booking-period type plus a period number resolves to calendar dates only through the annually re-issued decade plan and the municipality's pasting block, whose start dates and head/tail exceptions are carried as data in the reference implementation | reported | [sdaw-import](https://github.com/mckoch/sdaw-import) calendar and code tables; via the contributed analysis | 2026-09-08 |
| The record carries illumination class, physical height and width in centimeters, construction type, municipality key, postcode, a site photograph name, price in cent per day per panel with no currency field, and one performance metric class plus one performance value | reported | [sdxist](https://github.com/mckoch/sdxist); via the contributed analysis | 2026-09-08 |
| Availability is a full snapshot: a panel absent from the availability file is fully booked, with no deltas, no sequence numbers and no time component on the header date | reported | [sdxist](https://github.com/mckoch/sdxist); via the contributed analysis | 2026-09-08 |
| SDAW carries no authentication: the sender and lessee fields are identifiers rather than credentials, and integrity rests on total records | reported | [sdxist](https://github.com/mckoch/sdxist); via the contributed analysis | 2026-09-08 |
| The owning association, the Fachverband Außenwerbung, was renamed B|A|M Bundesverband Aussenmedien in 2025, and its current site does not mention SDAW; no public source discusses the format after roughly 2013 | reported | [B|A|M](https://aussenmedien.de/); [outmaxx glossary](https://www.outmaxx.de/lexikon/standardisierter-datensatz-zur-aussenwerbung-sdaw/); [schwarz-aw glossary](https://schwarz-aw.de/aussenwerbung-lexikon/) | 2026-09-08 |
| The German audience figure for classic poster sites, Plakatseher pro Stelle, replaced the older G-Wert from 1 January 2013 | shipped | [Plakatseher pro Stelle](https://de.wikipedia.org/wiki/Plakatseher_pro_Stelle) | 2026-09-08 |

## Open questions

Carried into `docs/research/README.md` so the discovery pass works them.

- **Whether SDAW is still actively exchanged in 2026, and whether B|A|M still
  maintains it.** No public source after roughly 2013, and the association's own
  site is silent. This is the question that decides how much the rest of the page
  matters. Newly open.
- **The contents of the members-only specification** — about 24 file types,
  roughly 220 record bytes including one 140-byte block, the site-class and
  price-group appendices, the character set, the filename mask and the transport.
  Only association access closes it. Newly open.
- **Whether the file-type codes for reservation, confirmation, posting order,
  proof of posting and invoicing exist under names this reconstruction never
  saw** — a gap in public knowledge, not necessarily in the format. Newly open.
- **Whether any SDAW-to-IDOOH or SDAW-to-OpenOOH mapping exists.** None was
  located, in either direction. Newly open.
- **Whether AdCP's static-OOH draft advances into a released schema, and on which
  version.** The identifiers a German binding needs (`ooh` property type,
  `panel_id`, authority-prefixed measurement references) are drafted and were
  verified absent from the released enumerations by the contributed analysis; that
  absence was not independently re-checked here. Newly open.
- **Whether AAMP's out-of-home intent produces an artifact**, or whether its
  OpenDirect-derived vocabulary remains its only out-of-home surface. Newly open.
- **Whether the German audience figure could be carried as a recognized
  measurement authority rather than a seller-modeled estimate**, which depends on
  AdCP accepting an authority prefix for markets without a joint industry
  currency. Newly open.
- **Whether any German or wider DACH media owner has an agentic out-of-home
  implementation.** Unchanged from the 2026-09-04 OOH note; this note adds the
  German market's side of it without closing it.
